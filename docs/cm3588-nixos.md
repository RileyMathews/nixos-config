# NixOS on CM3588 Board Installation Guide

> Originally posted by [PatrickHuetter](https://github.com/PatrickHuetter) in
> [edk2-porting/edk2-rk3588#142](https://github.com/edk2-porting/edk2-rk3588/issues/142#issuecomment-2662769408).

I also got NixOS running on my CM3588 NAS board :)

For everyone who's interested how I got it running, here are the steps in short. Big thanks to @sanderhollaar, @jjpe, and @NomisIV for sharing your knowledge here. This helped a lot!

This guide explains how to install NixOS on a CM3588 board, starting with an initial EDK2 (UEFI) installation and then setting up NixOS on the eMMC. The system boots from EDK2 using a mainline Linux kernel (6.13.2) with full hardware support (HDDs, NVMe, eMMC, and SD cards are all recognized). The only missing component is ZFS support (to be added later for your HDD pool). No modifications in EDK2/UEFI were required.

---

## Part 1: Installing EDK2 on eMMC

1. Flash the EDK2 image on eMMC:
   - Flash the OpenWrt-friendly FriendlyWrt image (eflasher mode) onto your board. This image automatically installs onto the eMMC when you insert the SD card.
2. Install EDK2 via the OpenWrt interface:
   - Use the OpenWrt web interface (with MMCTools available in the UI) to upload and install the EDK2 image.
3. Important note:
   - After this installation, the eMMC contains only one partition (the U-Boot partition holding UEFI/EDK2).

---

## Part 2: Installing NixOS

### Pre-Installation Steps on Debian

1. Prepare the microSD card:
   - Flash Debian Core Bookworm onto a microSD card and boot the board from it (the board always boots from the microSD card first).
2. Install Nix and enable experimental features:
   - Run the following commands on Debian to install Nix in daemon mode and enable flakes and `nix-command`:

```bash
curl -L https://nixos.org/nix/install | sh -s -- --daemon
echo 'extra-experimental-features = flakes nix-command' | sudo tee -a /etc/nix/nix.conf
nix shell -- nixpkgs#{coreutils-full,dosfstools,f2fs-tools,fscrypt-experimental,gptfdisk,nixos-install-tools,util-linux,vim}
```

### Partitioning the eMMC

Using Debian, create two additional partitions on the eMMC for NixOS (the existing UEFI/U-Boot partition remains unchanged).

Target layout:

- UEFI/U-Boot partition: contains EDK2 (already present)
- `/boot` partition: VFAT formatted, label `NIXBOOT`, size 512 MB
- Root filesystem partition: ext4 formatted, label `NIXROOT`, using the rest of the eMMC

Notes:

- You may need to adjust the GPT table so that the full size of the eMMC is recognized. Use either `gdisk` (recommended) or `parted`.
- Verify your eMMC device. It may differ between systems; in this example it is `/dev/mmcblk2`.

### Formatting the Partitions

Format the new partitions with:

```bash
sudo mkfs.vfat -F32 /dev/mmcblk2p2
sudo mkfs.ext4 /dev/mmcblk2p3
```

### Mounting the Partitions

Mount the partitions to prepare for the NixOS installation:

```bash
sudo mkdir -p /mnt-nixos/boot
sudo mount /dev/mmcblk2p3 /mnt-nixos
sudo mkdir -p /mnt-nixos/boot
sudo mount /dev/mmcblk2p2 /mnt-nixos/boot/ -o umask=077,fmask=0077,dmask=0077
sudo systemctl daemon-reload
```

### Generating and Adjusting the NixOS Configuration

1. Generate the configuration:

   ```bash
   sudo nixos-generate-config --root /mnt-nixos
   ```

2. Edit the configuration:
   - Before installing NixOS, edit the generated `/mnt-nixos/etc/nixos/configuration.nix` file. Use the example below as a base configuration that worked on the original author's setup.
   - This configuration sets up DHCP networking (ensuring the board connects to the Internet) and configures OpenSSH for remote access. The OpenSSH setting uses `services.openssh.settings.PermitRootLogin` with a capital `P`.

Example `configuration.nix`:

```nix
{ config, lib, pkgs, ... }:

{
  imports = [
    # Include the hardware configuration generated by the scanner.
    ./hardware-configuration.nix
  ];

  boot = {
    kernelPackages = pkgs.linuxPackages_latest;
    loader = {
      efi.canTouchEfiVariables = true;
      systemd-boot.enable = true;
    };
  };

  hardware = {
    deviceTree = {
      enable = true;
      name = "rockchip/rk3588-friendlyelec-cm3588-nas.dtb";
    };
  };

  # Set your time zone.
  time.timeZone = "Europe/Berlin";

  # Enable DHCP on all interfaces.
  networking.useDHCP = lib.mkDefault true;

  # Enable SSH and allow root login (adjust for security as needed).
  services.openssh.enable = true;
  services.openssh.settings = {
    PermitRootLogin = "yes";
    PasswordAuthentication = true;
  };

  environment.systemPackages = with pkgs; [
    vim
    git
    htop
    # Add any additional packages you need.
  ];

  # Do not change this after installation.
  system.stateVersion = "25.05";
}
```

Example `hardware-configuration.nix`:

```nix
{ config, lib, pkgs, modulesPath, ... }:

{
  imports = [
    (modulesPath + "/installer/scan/not-detected.nix")
  ];

  boot.initrd.availableKernelModules = [ "nvme" "ahci" "usbhid" ];
  boot.initrd.kernelModules = [ ];
  boot.kernelModules = [ ];
  boot.extraModulePackages = [ ];

  fileSystems."/" = {
    device = "/dev/disk/by-uuid/96bcea9c-10e4-48e5-a8bd-4656116bc43b";
    fsType = "ext4";
  };

  fileSystems."/boot" = {
    device = "/dev/disk/by-uuid/267E-228D";
    fsType = "vfat";
    options = [ "fmask=0077" "dmask=0077" ];
  };

  swapDevices = [ ];

  networking.useDHCP = lib.mkDefault true;

  nixpkgs.hostPlatform = lib.mkDefault "aarch64-linux";
}
```

### Installing NixOS

Once you have adjusted the configuration, install NixOS onto the eMMC:

```bash
sudo nixos-install --root /mnt-nixos
```

---

## Final Steps and Outcome

1. Reboot the board.
2. Remove the microSD card during the reboot so that the board boots from the eMMC.
3. After rebooting:
   - You now have a running NixOS system that boots from EDK2 with a Linux 6.13.2 kernel.
   - All hardware (HDDs, NVMe drives, eMMCs, and SD cards) is recognized.
   - The only component still to add is ZFS support for the HDD pool.
   - No modifications were required in EDK2/UEFI, and the system is running on a mainline kernel.

You can now connect via SSH (ensure that your network and OpenSSH settings are correct) and continue configuring your system as needed.
